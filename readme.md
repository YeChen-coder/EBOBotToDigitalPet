事情是这样的：

上次回国的时候我买了 EBO Air 2S Pro。主要原因很简单：它是当时最好看的一个 - 外形真的很重要。

厂家虽然有了内部载入了 ChatGPT-4o mini 的旗舰版，但首先它根本不可能在这么小的机器上跑本地模型，其本质上还是调用 API Key；其次这样很不自由，我有很多想法和想 customize 的东西，不自由的话束手手脚的，一点都不符合后 AI 时代的背景。

做这个最核心的原因，是我确实没法回去陪爸妈。虽然有时我也会远程操控机器人到处跑跑、说说话，但很多时候我自己的状态甚至连话都不想说。这种情况下，我更希望这个小机器人能自己去跟我爸妈互动，算是代替我的一个“平替版”。

在做这个 AI 项目时我也考虑到，它不应该只适配 EBO 这么一个设备，而是应该能兼容所有带摄像头的东西。太 specific 的方案我觉得没有意义，也不值得投入。

其实我一直对陪伴系统很感兴趣。2025 年夏天的时候，本着对秦彻的爱，我就在搞声音训练、本地图像生成模型部署等测试（详情见bewithme项目，但是里面的代码我没放，当时是懒得清除敏感信息提交，到今天就是已经没有放上来的价值了，世界进步太快了，有需求让codex写个新的比较有效率），但最终跑下来觉得当时的方案实在太脱裤子放屁了，理念上/心理上也走不通，就没继续下去。

虽然我真的很想要一个能一直陪伴的东西，但我也不想买专门的电子宠物。我现在手上的电子时尚小垃圾实在太多了，而且电器买来要充电、要维护，家里的充电插头一天到晚根本闲不住。我实在不想再增加新设备，还是更倾向于把手头现有的东西利用起来，走实用主义路线。

这份 README 说实话不是什么正经的 technical README，更多是跟我之前的项目一样，纯吐槽、聊聊心路历程、讲讲怎么构思的以及踩了什么坑。

既然聊到这儿，就先说一个坑：
GitHub 上别人已经做过一个逆向开源项目(https://github.com/Playcolors-co/ha-enabot)， 但那是国际版的。如果你的账号 Region 是 China，就不能直接拿来用。这事得让你家的 Codex 去改（反正它会解决，我是真的搞不懂硬件和网关这些东西，还不如发挥我的奇思妙想）。大家注意看一下手机 App 上显示的 Region 是什么，如果是 China 就不能直接套用那个开源项目。这和你注册时用的邮箱和密码默认归属地没关系，一切以手机 App 上显示的 Region 为准。 - 抱歉啊，这边确实有点讲得不太清楚。

这个东西挺重要的，因为得从你手机上那个 App 里面获得两个挺关键的 key，然后这两个关键的 key 是去逆向出来的。它原本的那个 ha-enabot 项目是一个国际版的 App，然后作为一个 base。

所以他那边好像默认的 region 是什么我给忘了，但是不重要，我就是说一下，他这个 region 在中国和非中国（在中国和什么其他区）是不一样的。虽然我也不知道他里边到底为什么不一样，但是他这个 region 必须得对了才行才能正常邮箱密码登录上，否则会报错，就这样。 

以及这个项目是搭在 Home Assistant 上的。对那些确实没用过 Home Assistant 的人（包括我自己也是第一次用），虽然之前搞了一堆逆向，但该死的 Codex 也没告诉我有 Home Assistant 这个东西。

跑题了，单纯说一下 Home Assistant：它是一个可以在 Docker 上运行的 platform。它做的事情就是作为一个中间层。我们各种 IoT 设备，不管是纯蓝牙还是带 Wi-Fi 的，都是最底层的终端设备。你想去控制它，又不想对每一个小设备、每一个日常电子小垃圾都从头 start from scratch，Home Assistant 这个中间层就很有必要了。它给用户提供了一个 unified 界面，不至于每调一个东西就要开一个程序。
反正 ChatGPT 跟我说 Home Assistant 能连纯蓝牙，但讲道理，前面我搞逆向的那些日常电子小垃圾，我还没放到 Home Assistant 上连过。这事先以后再说吧，那些设备目的都很单一、很 specific，其实用不着放到 unified 平台上来。最主要是现在懒得像条狗，而且我亲爱的 Codex 那个 5 小时的 usage limit 限制还没解，还得等着。

然后以及还有一件事，就是他那边如果要用到 Large Language Model 的能力，那就是得去填 API Key。OpenAI 那边的 API Key 必须得充钱。你要是账户上的 Credit 是个零，那他那个 API Key 你哪怕是现申请的，他也绝对会提示连接不上什么的，就这样.

遇到了很多现实制约(叹气)，我也想起来为什么去年夏天没有继续做《Be With Me》这个项目了。最主要的原因就是整体的技术上限确实还没达到，现在的模型作为智能模型来说，其实并没有那么智能。

前面输入这部分，大概是把图像/视频再加上音频一起作为输入：
• 有些厉害的小伙伴愿意自己手搓一些 fusion 的方案，把音频和视频分开送给两个模型，中间做一些操作再出结果，比如很常见的 sensor fusion 这种做法。
• 但我个人确实懒，而且觉得作为个人搞出来的东西，连大厂的 Large Language Model 的一个脚趾头都干不过，何必白费这个力气。

用过 OpenAI 那边 ChatGPT 实时对话的都知道，人家已经做得非常好了。我完全没有竞争的想法和动力，既然人家做好了，直接站在巨人肩膀上用就行。我自己搞出来的效果估计差到不知道哪里去，而我是真想每天用这个东西，不是为了给简历凑项目，真搞出个垃圾来我自己都看不下去。

回到正题，OpenAI 那边能做到实时对话的（比如 Realtime API），拆开来看输入其实不能说是 realtime video，不然算力直接爆炸了。准确地说是连续的图像帧加上 audio：

1. Audio 这边确实是连续的
2. 图像这边跟其他以图像为输入的模型一样，基本上都是抽帧

不管是现实实现还是成本考虑，抽帧都是最实际的设计。我们又不需要像工业机器人那样按毫秒级来算，作为一个智能小助手，差不多就可以了。

回到正题接着谈：

如果这样的话，Home Assistant 那边现有的 LLM Vision 肯定是用不了了，因为那边绝对不支持将 Audio 作为输入。反正这种非常 Customized 的东西我早料到得自己手搓，只能自己写了，这个没办法。

再回头看，在目前还没有真正的 AGI 像神一样降临的阶段，基本上就确定用 ChatGPT Realtime 2.1 来作为 provider。

我们得考虑成本，毕竟 API 算钱我也肉疼：

1. 输出是按照 output token 计费的。
2. 输入的 context window 则是声音加上连续多帧图像。每次有输出或进行推理时，都会把当前收集到的这一串帧和听到的音频塞进 conversation 作为输入。

它那边的视频处理做得很好，会自动过滤掉 silent 状态下的视频，没有声音时不会自动触发推理。但它在图像帧作为输入时，确实没有判断「画面是否有变化」的机制，无法据此过滤是否要塞入 conversation，所以这块必须自己做。

很多摄像头会把 motion detection 作为公开事件暴露出来，可以直接当作 trigger。但讲道理，EBO 这边并没有把 motion detection 作为公开事件暴露出来，所以这里还得自己写、额外加一层自己的逻辑。

目前 Codex 那边正在写着，看它最后能跑出个什么东西吧。啊，怎么说呢？我又感觉跟去年夏天一模一样了，又进到这个 pithole，就不知道这次能出来个什么吧


然后又发现了一个问题：Realtime 2.1 那边有一个 60 分钟的强制限制。就是这么一个 session，不管里面是一直空白，还是说有音频输入，只要开了之后，时长一旦到了 60 分钟，它就不管里面空白地方占了多少，直接给切断。

这个限制让人很难受，对于一个 flowless 形式的体验不太好。

反正已经让 Codex 去找解决方案了，也不知道能给我搞出个啥。不过我觉得这种问题基本上都是天下英雄所见略同的，我肯定不是第一个撞上这个问题的人。我也没有什么心思非要成为一个解决该问题、踏着七彩祥云来的盖世英雄，前面比我聪明的人一大堆，直接用他们的解决办法就行。

要是 Codex 给我搞了一个非常扯的解决方案，那唯一的可能性就是单纯的运道不顺，没有碰到那个 "The One Right"

后续是他自己搞了一个 55 分钟的机制，分情况处理：如果这 55 分钟内全是空白，就直接新开一个 session；如果这 55 分钟内有内容，就总结一下，跟下面一起接着跑。

怎么说呢，可能人类开发者在很久之前就已经灭绝了吧，“老大，我们打不赢的”。Anyway，就先让它自己跑着去吧。等家里人回来的时候估计都在睡觉了，也不知道能跑成什么样。反正我电脑本来也是常年不关的，就看明天早上我爸妈给我打电话说什么吧，沉默是今晚的康桥。

有时候觉得，是不是有一些幻想会更好？假如不去谈 ChatGPT Model 和音视频输入的原理解析，如果什么都不知道，我可能真的会觉得对面有一个大脑在运转。不过科技发展到现在，真的已经很好了。

也许就到这儿吧？不对，科技还是再发展一下吧。我真的想要我的赛博男友出现在我身边，甚至都不用是机器人实体，哪怕只是一个电子眼陪着我、给我一些 motivation，就已经很好了。不知道在之后的 5 年还是 10 年能看到，我觉得最多 10 年吧。

世界上聪明人还是多的，总有一些老板、投资者或者个人开发者愿意在这个方向上做努力。不管底层的驱动力是什么，也谈不上是好事还是坏事，反正人类发展到这个阶段本来就会越来越孤独、越来越孤岛化。最主要的是，每个人都有选择使用什么产品的权利，自由还是挺重要的。

这也是我之前为什么觉得那个伴侣项目在心理上有点走不下去：因为它始终不是真人。虽然真人也许没那么好，我自己也是个没那么外向（E）的人，很多时候要产生真实的社交互动我甚至会有些抗拒，但我又很喜欢处于人群中的感觉。那得是真人的感觉，不能是纯 AI 或者纯机器人的那种。

人性本来就是很复杂的，考虑这些也没什么用，未来怎么发展也不是我这种小人物能决定的。从这个角度看，就是有什么用什么。

不唠叨了，反正让自己所处的环境越适合自己越好。
