## 已确定的边界

- Watcher、diagnostic-service、一线 Codex、高级 Codex 分别独立容器。
- 运维系统独立 Compose 项目，不导入业务模块，不修改运行中的业务代码。
- 固定恢复成功并通过持续复检：记录后结束，零模型调用。
- 无适用恢复流程、有限恢复失败或短期反复故障才创建诊断任务。
- 一线可选 Codex SDK、API 或禁用；高级默认 Codex SDK。两级模型和推理强度分别配置，以 HTTP job 协议替换 provider。
- 模型结论不能关闭故障；只有 Watcher 的实际健康复检可以关闭。
- 宿主机操作桥只允许配置内的 Docker 或 ECS 目标检查与恢复。Codex 没有 Docker socket 或 AWS 凭据。
- Docker 整体失效由宿主机 guardian 处理；容器不可用时直接本地通知。
- 第一版 AI 深入排查为只读；自动处置由固定恢复手册执行，AI 给出进一步建议。
- 主动停用/维护不自动拉起；不会开麦、移动机器人或调用业务写接口。

## 验收场景

1. 暂态异常/启动期/主动关麦不触发模型或重启。
2. 适用故障重启一次后持续健康：零模型调用。
3. 重启无效、反复退出：同一故障只提交一个诊断任务。
4. Watcher 重启后恢复故障与操作预算，不重复执行已发出的重启。
5. API 未配置自动跳过；provider 失败/超时产生可见结果。
6. 模型报告正常但健康检查失败：故障保持打开并通知。
7. 通知失败可重试；诊断进度不阻塞故障通知期限。
8. 宿主机操作入口拒绝未授权目标、任意命令与重复操作。
9. 独立测试服务的容器集成验证不打断真实 EBO。

## 后续可选扩展

- 接入 Telegram token/chat id 和一线模型 API；目前已保留环境变量与适配器。
- 增加 HA 登录后的功能探针、扬声器端到端检查、更多经过验证的恢复手册。
- 增加其他高级 AI worker；复用 job 协议，不修改 Watcher。
- 若要覆盖用户注销或整机断电，增加外部主机心跳。
