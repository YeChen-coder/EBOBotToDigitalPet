## Local changes / 本地主要变化

- Added Frigate and Mosquitto to the local Home Assistant, Engine, and Assistant stack.
- Replaced the previous assistant implementation with the `specter-ebo-v2` session framework: voice wake, identity hints, finite conversations, primary transcript response gating, independent live transcription, per-user summaries and memory, and PCM talkback.
- Updated source audio/video health and transport behavior, playback guards, camera stability, and pause/resume controls.
- Updated the Diagnostic Agent's health contract, recovery decisions, source snapshot, prompts, five-service runtime control, Dashboard sessions, and conversation readers.
- Published current source, unit tests, portable startup/shutdown scripts, configuration examples, migration notes, and the updated Diagnostic Agent implementation/Host Bridge design documents.

新版引入 Frigate 图像与人脸识别、MQTT 身份提示和新的语音会话框架；同步发布 Diagnostic Agent 的健康判断、诊断 Prompt、源码快照、Dashboard 会话/暂停控制与测试。

## AWS status: NOT migrated / AWS 状态：尚未迁移完成

**The AWS side of the Diagnostic Dashboard for this release is unfinished.** The current publication updates the local stack and local Diagnostic Agent. Existing AWS adapters, IAM helpers, historical CloudWatch transcript support, and old deployment documents are retained for reference; their presence does not mean this architecture is deployed, operational, or validated in AWS.

**这次新版 Diagnostic Dashboard 的 AWS 端尚未做完。** 已更新的是本地业务和本地 Diagnostic Agent。旧 ECS/Fargate、CloudWatch、IAM 和云端切换代码保留，但旧版成功记录不能作为新版云端已经可用的证明。

The public example uses `runtimeEnvironment: "local"`, `runtimeControlScope: "local"`, and `requiredArchitecture: "specter-ebo-v2"`. With local scope, cloud start requests are rejected and local runtime actions do not query or stop AWS. Historical billing/read-only AWS utilities are separate capabilities and require their own configuration. Uploading this release does not deploy or change any AWS service.

Remaining work before enabling the new AWS runtime:

1. Design and deploy the Frigate/MQTT dependencies, network/storage, and updated Engine/Assistant images for AWS.
2. Migrate and verify the v2 health contract, session controls, source audio/video checks, transcript handling, and memory storage in the cloud environment.
3. Adapt and validate Dashboard cloud control, monitoring, bounded recovery, IAM permissions, and transition behavior against that deployment.
4. Confirm end-to-end behavior with the robot and current deployment; only then configure the cloud target's architecture and explicitly enable cloud control.

以上事项是待办，不是本次上传已完成的内容。仅改一个配置值或通过旧适配器单元测试不足以完成迁移。
